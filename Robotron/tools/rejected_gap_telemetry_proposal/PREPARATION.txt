ENABLE AND BOUNDS
Only replay_enabled=True AND ROBOTRON_REJECTED_GAP_TELEMETRY=1 enables recording.
The explicit flag is main-only in this proposal; replay-off private sidecars
remain disabled even if they inherit it. No current environment/control changes
are made. Tracking is at most 256 simultaneous connections, one pending gap and
one first-accepted closure in progress per tracked connection. Each handler's
finally removes its record. First32 scalar closure witnesses are retained
globally in closure-completion order, never overwritten or sampled with policy
RNG. Further closures increment witness_overflow; counts continue. Counters
saturate at 2^63-1 and invalidate availability. Tracking overflow and observer
exceptions also make available=False: zeroes then prove no absence. No state,
reward, replay array or tensor is copied or retained. No file/network/device I/O
occurs in the helper. Connection and per-connection receive sequences are
ordinary process-lifetime Python integers; collection cardinalities are capped.

DENOMINATORS AND FOLLOW-THROUGH
payloads_complete counts complete received payloads, before parameter/parser
validation; it is not socket read calls, wire bytes or physical replay inserts.
Separate fixed counters record parameter/short-payload exits and terminal header
idle/EOF/invalid-length/broken-body cases. Header polls returning None below the
idle limit are not counted as errors. parse_none, crash_jump and crash_drop are
unthrottled tracked parser/classifier outcomes, unlike existing printed warnings.
Consecutive rejections share one gap with first/last receive sequence and reason
counts. neutral_write_ok/failed report only the server sendall result for those
existing responses, not Lua receipt, button application or elapsed game steps.

The first accepted frame records classifier output and scalar client state
BEFORE existing first-frame, measurement and accepted-newgame resets, then records
state AFTER those real reset paths but before stacking/previous-step replay.
same_classifier_game requires positive UID continuity across all three snapshots
and no new-game classification. It is classifier continuity, not independent
ground truth about game identity or clean temporal attribution. Measurement
generation/active changes are recorded separately. UID0, reset UID changes, or a
closure interrupted before the after-reset stage cannot prove same-game status.
accepted_closures counts reaching the first accepted stage; disconnect_closures
also includes a later interruption, so these are stages, not disjoint outcomes.

The actual previous-step branch, nstep input and returned matured count, enqueue
calls/returns and next selected action are distinct fields. Actor-group switches
flush every old prefix BEFORE appending the current input: expert is one group,
all nonexpert tags are learner, exactly as held nstep_buffer.py. The observer
subtracts that pre-input flush count; those rows must not be attributed to the
current gap-following input. Later emitted suffixes contain the current input;
this is emission attribution, not proof of valid transitions. One-step fallback
is labeled separately. step_async called/returned does not acknowledge physical
insertion (it can return after stop), sampling, optimization or benefit. No such
physical-insertion claim is made. Reset-discarded pending tails and preserved
history/action metadata are visible without changing their behavior.

READONLY COLLECTION AND COST
snapshot() does not drain. Its own bounded diagnostic copy is lock-protected;
client scalars are captured at distinct insertion stages, and this snapshot is
not atomic with API clocks, journals, other clients or gameplay. Pending and
first-accepted-in-progress totals expose unfinished observations. The getter is
not wired into an API by this patch. Future low-rate collection should retain
observer process/instance identity, availability, start/end counters, pending/
in-progress totals and the bounded witness set; compare only the same instance.

Reviewed3 avoids locking stage events when their ticket is None; accepted and
receive events still take the diagnostic lock when enabled. Added call/keyword
evaluation overhead remains even with the flag off, and enabled counters briefly
serialize across clients. Snapshot deepcopy and witness-state conversions add
bounded cost. No overhead, throughput or quality effect has been measured. Keep
future collection infrequent, measure enabled/disabled cost under matched load,
and do not infer causality or a speed benefit from rates or conditional examples.
Current live occurrence is unestablished: a closed 60-second stdout observation
had zero printed reject warnings and nine accepted/coerced score dips; printed
warnings are throttled and some parser failures are silent, so this does not
bound all rejections. Existing accepted-game journals cannot reconstruct all
