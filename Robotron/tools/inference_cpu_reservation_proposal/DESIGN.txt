Question and scope
==================
The preliminary pin-only observation supplied by root was approximately70,199
applied-admission samples/s for B versus69,287 for A: below the precommitted5%
threshold even before comparison with Areturn. Inference ready-wait rose from
3.106 to110.063ms/s while migrations fell from328.6/s to0. These are motivating
observations, not a completed result or proof of contention as the bottleneck.

Prospective B gives the unique, identity-bound InferBatchWorke thread {71}, and
removes71 from every other thread in the exact trainer and192 exact main MAME
actors. On the currently described unrestricted masks this means {0..70} for
those other threads. A and Areturn use the original per-thread masks. There is
no process restart, model/config/actor-count change, cgroup restructuring, CPU
hotplug, system/IRQ isolation, or automatic adoption. Other host tasks, the
fleet supervisor, unrelated children/processes and this controller are outside
the treatment. Thus this excludes owned competitors, not exclusive OS-level
ownership of a physical core. CPU71 may have sibling/host scheduling effects;
online CPU and NUMA topology are precommitted, not reconfigured.

3. Capture ALL current threads in ALL193 owned processes with owner identity,

Applying B and keeping the interval well defined
==============================================
Install handled INT/TERM/HUP exceptions before launch mutation. Maintain a
rollback-capable state in memory and on disk before each treatment syscall.
With those handled signals temporarily blocked, journal owner/TID/start,
expected-current mask, requested mask and restore mask; fsync; reverify exact
owner/TID/start and expected-current mask immediately before the syscall;
register that exact task as POSSIBLY MUTATED in memory BEFORE the syscall;
write; read back mask+identity; then journal the outcome. A failing write or
interrupted readback is still a possibly changed task to restore. Never infer
unchanged merely because the syscall did not return normally.

Change non-inference trainer/actor threads first, including all process leaders,
then pin the exact original inference thread last. Exited non-inference tasks
are recorded, not confused with a reused TID. Repeat bounded discovery/readback
until all current tasks match the requested phase. No live process is stopped
to force an atomic fleet transition. Cross-thread transition is non-atomic and
outside the settled/primary windows. No new process is automatically adopted.

Per1s observation, enumerate owned thread sets and verify masks/TID start times;
every30s compare complete immutable process/fleet/environment/source/control
bindings, and immediately before any affinity syscall reverify the full owner.
Record scan duration and snapshot spread; if bounded complete checking cannot
keep up, fail rather than weaken guards or present a precise-time exclusivity
claim. The same checks run in A/B/Areturn. Their actual overhead is unmeasured.

New threads, thread exit and PID/TID reuse
========================================
Production creates BankPersistence on demand in replay_buffer.py:1432, socket
handler threads in socket_server.py:2559, and delayed cleanup Timers at2480;
other native/lazy worker creation is possible. The normal expected new-thread
mask follows its creating thread: after non-inference parents are restricted,
new bank/client/checkpoint-related work should already exclude71. This is an
expectation to verify for every observed task, not a claimed birth barrier.

For a NEW TID/start in the SAME verified original process:
* During B, an already correct0..70 task is accepted and journaled without a
  syscall, with the original owner's saved leader0..71 as restoration fallback.
  It has no literal pre-experiment per-thread mask; label the fallback honestly.
* A task born after treatment may inherit {71} from the pinned inference thread,
  or a still-unrestricted parent during transition. Once B writes begin, any
  newly observed non-inference task with {71} or any mask other than0..70
  INVALIDATES the trial, including transition and settle. Restore, retain all
  rows, and do not repair, reset settling or salvage the window. A short-lived
  task can begin/end between polls, so zero momentary competition is unproven.
* During A/Areturn require0..71. No new task with a surprising mask is normalized
  silently to make the interval eligible.
* A reused TID in that same owner is NEW, never the old thread's saved identity.
  A vanished task is recorded. Replaced/exited trainer or MAME process, changed
  slot/cgroup/owner, missing/replaced inference TID, or classified actor failing
  inspection invalidates immediately. Never write a replacement process.

Rollback, Areturn and failure semantics
======================================
Restore original masks before Areturn's settling and in one unconditional
finally for success, invalid observation, source drift, syscall/disk failure,
KeyboardInterrupt and handled INT/TERM/HUP. Keep handlers installed through
cleanup; defer repeated handled signals while all known owners are attempted.
Restore does not require unchanged controls/source/API/fleet cardinality:
those may be the reason cleanup is required. It DOES require exact boot/user/
project and the saved original process identity immediately before each write.

Per-task rollback is independent of GLOBAL health and fresh telemetry success.
Use the sealed original ownership/masks plus the in-memory POSSIBLY MUTATED set
established BEFORE each syscall, even if its outcome was never journaled. A
fresh journal/fsync/status failure must NOT prevent an eligible restore syscall,
abort an owner traversal, or skip the other owners. Record diagnostics on a
best-effort basis, continue all owners, and return unsuccessful/manual-recovery
status if complete mask verification or truthful evidence publication fails.
Do not report a durable recovery receipt if its write failed; use best-effort
stderr/exit status and retain the original sealed file for manual recovery.

Immediately before EACH rollback write, verify the saved exact owner, Tgid and
TID/start, and read that individual task's current mask. For an original task,
allowed rollback masks are its original mask and the masks this controller
durably intended/applied to THAT identity (including possibly-mutated attempts).
Restore its exact durable saved original. An unexpected mask outside that
per-task set may be another actor's mutation: skip that task, explicitly report
manual recovery, and continue restoring every other eligible exact-owned task.
Do not normalize an external change or make global health a rollback condition.

For a current NEW/reused TID in the SAME verified original owner, use the saved
original leader0..71 fallback, never a different process or an old reused TID's
identity. At rollback only, known masks0..70, {71}, and0..71 are eligible for
that fallback. In particular, a newly observed non-inference {71} INVALIDATES
B, but its plausible inherited experiment mask must still be restorable to
the original leader's72 CPUs. This emergency undo is NOT a treatment repair,
does not resume B, and does not salvage its data. Label fallback use honestly:
there was no literal per-thread pre-experiment mask for a newborn. Any other
unexpected newborn mask is skipped with manual-recovery-required evidence;
continue the other eligible tasks. Journal this distinction when possible.

Retry bounded8 passes until thread sets/readbacks stabilize. New threads can
inherit a narrow mask from a parent not yet restored, so one pass is insufficient.
Attempt every surviving original owner even if another owner or task fails;
never target a replaced PID. If an owner exited/replaced, classify it explicitly
and invalidate the experiment. Report original-mask restoration only for still-
owned eligible live tasks, never full-fleet success. Unrestorable live tasks,
unexpected external masks, unstable sets or unavailable proof require explicit
manual-recovery-required status with known remaining identities/masks.

An exclusive fsynced originals file plus ordered intents makes crash recovery
reviewable, but SIGKILL/power loss cannot run finally. A future root-owned
restore-only command must use that snapshot/journal and exact identities, with
no broad kill, PID search replacement, or automatic adoption. Linux affinity
accepts numeric TIDs: immediate start/Tgid/owner checks cannot eliminate reuse
between verification and syscall. State this unavoidable API race.
