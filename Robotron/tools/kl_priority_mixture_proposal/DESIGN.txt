Exact algorithm boundary
========================
Keep loss=(weights*CE).mean()+the existing expert auxiliaries. Never backprop
through KL, entropy or priorities. CE, CE slice diagnostics, target construction,
support[-10,50]/51atoms, gamma, stored n-step reward/horizon, done masking and
the current zero target smoothing remain unchanged. Use the SAME executed
projected/smoothed FP32 target m and taken-joint-action CE for priorities:
  H(m)=-sum(m*log(clamp_min(m,1e-12)))
  metric=max(0, stop_gradient(float32(CE)-H(float32(m))))
Do not do another stochastic/noisy forward, use raw preprojection entropy,
renormalize m, special-case terminals, or discount the stored n-step return again.
For done rows the bootstrap is zero; the reward can still project across two
atoms. Exact-bin and clipped-support rows must retain the actual projection.
CE-H is literal KL only for a normalized nonnegative target distribution. Retain
target mass error, raw signed CE-H, negative/near-zero counts and extremes before
clamping; clamping is not evidence that a materially negative result is valid.

Actual update_priorities then filters bank sentinels and writes
  leaf=(abs(metric)+1e-6)**alpha, alpha=0.7.
Thus metric0 produces a strictly positive epsilon**alpha leaf, not a zero leaf
or a1e-6 priority-space leaf. Config.priority_eps is NOT read by this method.
The entropy log floor1e-12, sampler's leaf floor1e-10 and insert priority floor
1e-6 are different conventions. Do not conflate or change any of them in rawKL.
The old eager entropy diagnostic uses1e-8 whereas the compiled diagnostic uses
1e-12: neither aggregate diagnostic alone certifies per-row candidate priorities.

The patch preserves the four-output TrainingLoss default but opts production
compiled callers into a fifth output even for CE. Validate default-CE actual
CUDA/AMP/compiled ABI and readback-offset/outcome parity, then eager and diagnostic
variants. The kernel binds the metric at construction; training.py reads cfg.
Treat selection as restart/rebuild-only and require their metric identities to
agree. No hot control change or silent fallback. No optimizer/scaler/AMP tuning.

Actual4096-row mixture and objective conventions
================================================
Draw order is PER ring, interesting ring, recent ring, HOF, EpHOF. Preserve
explicit origin slices from sampling time: duplicate/overlapping indices cannot
reconstruct which proposal selected a row. Only PER rows receive normalized IS:
  w_i=(minimum selected clamped PER priority / clamped selected priority_i)^beta
when the production max-weight denominator is active. Beta reaches1 after its
actual nonmeasurement-fleet-frame schedule, not after accepted inserts.
Use the emitted/staged weights; the tree may change while prefetch waits.
Recent and interesting weights are1; each bank row gets THIS batch's mean PER
weight. Banks are uniform valid-slot draws with no PER leaves. Bank staleness,
minimum transitions and interest shortfalls alter quotas; never infer live mix
from comments. Nominal eligible/nonstale/full-interest4096 default counts are
PER901/interesting737/recent1434/HOF410/EpHOF614, not75% PER. Record actual counts.

Only Bellman CE is IS-weighted. Expert BC is an expert-subset mean multiplied by
max(BC_floor,scheduled_BC*expert_fraction); Q-policy/margin are expert-masked
sums/B with their scheduled coefficients. None gets replay IS weights. Log
these terms separately by stored is_expert/actor_kind and origin. Eval-origin
rows are stored with DQN actor_kind, so that byte cannot recover eval identity.
Bank downweighting changes Bellman-versus-expert balance even without changing
any explicit coefficient. Such induced balance is part of rawKL, not a reason
to force mean-weight equality or adjust LR. A common leaf multiplier cancels
from batch-normalized IS away from fixed floors/hints; it is not a general fix.

Migration must be an explicit part of the hypothesis
===================================================
Proposed first rawKL branch: start BOTH branches from the same CE-priority tree;
retain historical max, reward hints, cap3*mean and all existing boosts/floors.
B converts only subsequent sampled ring rows, including recent/interesting;
banks remain unprioritized. Priorities update even when AMP skips: preserve that
behavior and distinguish conversion from applied learning. Preserve ring-index
ordering/duplicates, bank sentinels and any prefetched private batches/reset rule.
Do not retrospectively rebuild the entire tree, reset its maximum or hide a
post-switch interval. A full-tree conversion would be a different experiment.

New rows still begin at historical max, capped to3*current mean, raised by
abs(reward hint)**alpha then capped again and priority-floored. Terminal hints
can be raised to the death boost; elite/predeath multiply existing leaves.
These scales do not cancel in a CE/KL mixed tree. Boosts can raise historical
max and a normal reprioritization can erase a boost. Track insertion cap/hint
saturation, boosted-event exposure and metric/conversion age per valid ring
generation, including overwritten slots. Newly inserted hint-seeded leaves are
not automatically CE- or KL-evaluated leaves. All accepted ring sources count
toward physical turnover; accepted DQN+epsilon is a separate learning clock.

Replay persists raw leaves plus[ptr,size,historical_max] without a metric tag.
Before any learning trial, require matched versioned provenance/sidecar for
metric, migration, source, conversion generation/state and coherent anchor;
resume must reject missing/mismatched provenance rather than relabel old leaves.
Run config/environment metadata alone cannot certify a replay tree's contents.
