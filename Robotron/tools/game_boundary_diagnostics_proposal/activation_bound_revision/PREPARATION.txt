Data, allocation and boundaries
  Same primitive accepted-sample scheme as the original source proposal:
    previous/current parsed wire score, wave, alive, done, start, lives and
    connection-local accepted-frame count before increment; actual prior
    classifier score/wave/alive baseline, last_start_frame before/after this
    frame's start update, actual recent_start/verdict/new_game.
  Score/wave copy occurs before coercion/unwrapping. Prior wire and classifier
  baseline are separate because an accepted torn-score frame can be coerced.
  No full wire/RAM/model state, recent history, extra RNG, thread or lock.
  Client storage is one previous accepted primitive tuple; enabled loop locals
  also briefly retain previous/current/input tuples. Rejected frames do not
  advance the accepted tracker. Reconnect's first previous sample is null.
  Existing source/config pins are needed to interpret thresholds and gates.

  OFF has only branches/None arguments and no diagnostic tuples/dicts/client
  key. ON builds two small tuples per accepted frame and expands a small dict
  at existing journal _begin. It adds game_boundary_diagnostics to start context
  in the existing admission/completion records, without an additional write.
  Initial attachments and journal zero_score_restart are truthfully separate
  from classifier_new_game. No performance overhead measurement is claimed.

  NEW minimal later-first-play evidence: inside the EXISTING first_play_level
  assignment, a measured known game whose first playable level is not1 copies
  that frame's primitive inputs to start_context.first_play_not_wave_1_inputs.
